# SNES.dll 1.7.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the pinned `lib/SNES.dll` from v1.6.0 to v1.7.0 and put the release's new ROM identity into the `SNS` lines of `counters-debug.log`.

**Architecture:** v1.7.0 is a drop-in for this consumer — its one breaking change is `Smc()` returning an identity slug instead of a ROM path, and SMWCounters never calls `Smc()`. So the bump is a binary swap, and the only code work is threading two render-only strings (the ROM identity slug from the status snapshot, and the emulator's raw window title from a cache) into the existing log-on-change filter. Nothing branches on ROM identity.

**Tech Stack:** C# / .NET Framework 4.8.1 (component), netstandard2.0 (SNES.dll), xUnit, MSBuild + `dotnet` CLI, Windows.

## Global Constraints

- **Close LiveSplit before every build.** The post-build `CopyToLiveSplitComponents` target copies into `C:\Apps\LiveSplit\Components`; a running LiveSplit locks the loaded DLLs, the build still "succeeds" with a warning, and every later observation is then made against stale code.
- **Target pin: SNES.dll v1.7.0**, built Release from the sibling `snes_offsets` checkout at commit `23a56a2`. `FileVersion` must read `1.7.0.0` before it is copied. Never pin a Debug build.
- **Repo paths:** SMWCounters is `c:\Users\thedo\git\SMWCounters`; snes_offsets is `c:\Users\thedo\git\snes_offsets`; the LiveSplit checkout `SNES.csproj` references is `c:\Users\thedo\git\LiveSplit`.
- **ROM identity is render-only.** Per `snes_offsets/docs/status-first-consumption.md`, `Rom`/`RomSlug` are churn tier: render them, never split-path on them. v1.7.0 documents a transient where an identity can commit wrong near a ROM load before correcting itself — logging tolerates that, logic would not.
- **Committing directly to `master` is authorized** in this repo (see `CLAUDE.md`); no feature branch is required.
- Spec: `docs/superpowers/specs/2026-07-31-snes-dll-1.7.0-upgrade-design.md`.

### Task 3: Feed the identity from the connection

**Interfaces:**

- Produces: `SnesConnection.WindowTitle` (public `string`, `""` when detached or unavailable) and `DebugLogger.LogStatus(SNES.EmuStatus status, string windowTitle)`.

**Why the slug is read from the status rather than passed in:** `Rom` rides the same coherent snapshot as `StateName`/`Generation`/`WramBase`, so reading it there keeps every logged field from one snapshot with no chance of skew. The window title is not on the snapshot — it is a live Win32 call — so it is the only value that has to be handed in.

- [ ] **Step 2: Add the public members and the refresh**

Still in `SnesConnection.cs`, add after the `IsAttached` property:

    // Raw emulator window title — the human-readable half of the ROM identity
    // in the debug log ("clean - Snes9x 1.63"). Deliberately unparsed, per the
    // consumer contract: every emulator decorates it differently and a
    // prefix-stripping table would be exactly the kind of per-build table
    // SNES.dll deleted. "" when detached or unavailable.

    // ROM identity slug (v1.7.0), "" before SNES.dll finds one. Render-only:
    // the contract puts it in the churn tier, and an identity can commit

and add this method at the end of the class, after `ErrorSuffix`:

```csharp
    // emu.WindowTitle() does a Process.Refresh() + MainWindowTitle read, which
    // has no business running 66x/sec on the poll tick. The title can only
    // become newly informative when the process changes or a new ROM identity
    // lands, so refresh on exactly those.
    private void RefreshWindowTitle()
    {
        if (process == null)
        {
            WindowTitle = "";
            titleProcessId = -1;
            titleSlug = null;
            return;
        }

        string slug = RomSlug;
        if (process.Id == titleProcessId && slug == titleSlug) { return; }

        titleProcessId = process.Id;
        titleSlug = slug;
        WindowTitle = emu.WindowTitle(); // never throws; "" when unavailable
    }
```

## Notes for the reviewer

- **No csproj change is expected anywhere in this plan.** The reference is a `HintPath` into `lib/` with `Private=true`, and `CopyToLiveSplitComponents` already deploys the pair. If a task wants to edit a csproj, something has gone wrong.
- **No version bump, no release.** The pin ships with whatever release comes next (spec decision 6).
- **The settings status line and status pixel are deliberately untouched.** v1.7.0's header-aware `LastError` (e.g. *"SA-1 cartridge detected (slug); SA-1 WRAM discovery is not supported"*) already flows through `SnesConnection.ErrorSuffix`, so better decline text arrives with the binary alone.
