## Patterns observed by lenses

### Architect
- The seam is one byte wide (ISnesMemory = ReadWramByte), so every counter re-derives the same facts; ~40 reads/tick, same edge computed 3-4×. A per-poll snapshot with shared derived edges would collapse MidwayExitBankDetector and the duplicated death detector, and let DebugLogger log derived facts instead of re-deriving.
- Sharing happens by inheritance where composition would do; HasBankToggle is the visible seam of the missing counter-options abstraction.
- Testability tracks the seam boundary exactly: everything behind ISnesMemory has tests, everything outside (component, settings, connection, logger) has zero. Splitting settings model from view and renderer from component moves the most untested logic inside the tested perimeter.
- Test helpers mirror source duplication; SmokeTest and the dead-signal ExitCounter test are deletion candidates.

### Control inversion
- The counter-side seam is excellent; the shell around it has none — the untested surface is exactly the set of classes that construct rather than accept.
- Read amplification has a zero-counter-change fix: a memoizing decorator, since ISnesMemory already is the seam.
- "Flush by lying about attachment" (InertMemory) makes emulator-gone and timer-stopped indistinguishable; un-banking reconcile sits behind IsAttached so toggling discard-on-death while stopped doesn't reconcile until a live poll.
- Poll() does four jobs (discovery, counting, status-string push, logging); Describe() rebuilt every tick regardless of dialog visibility.
- Presentation lives on the connection object; StatusDot demonstrates the better shape.

### Test skeptic
- The fake is the right call and stops one layer too early; the two highest-value additions are a settings round-trip test and an IEmu-shaped seam, not more counter tests.
- Copy-paste between counter test files (~60 redundant lines in Powerup/BankToggle).
- Two regression tests pin $1935 which production doesn't read; one is redundant.
- The settings→counter wiring is the untested hinge: the checkbox could wire to the wrong counter id and the suite stays green.
- No flakiness, no slowness; poll-count-based timing is exactly right.

### Dead code
- The comments are unusually good, which is why the stale ones cost more — the house style trains you to believe the prose.
- Two kinds of "kept for later": healthy (optional diagnostic params) and rotted (expired "remove once confirmed" notes). Grep for "future use"/"unverified"/"Remove or repurpose" is a cheap recurring audit.
- Stale `using LiveSplit.UI;` is a reliable fingerprint of files predating the BankedCounter extraction.
- Micro-fossils: no-op Dispose, MinimumHeight setter never invoked.
- Dot/text drift: StatusDot grays cooling Discovering; Describe() omits the suffix.

### Types
- The internal/public boundary does more damage than it prevents; every crossing degrades into delegates and tuples. Nothing forces the settings class public.
- "Pure class takes primitives" applied one level too literally: define the boundary type in this assembly, get isolation without 11-arg methods.
- One fact, two owners, synced per tick (Banked vs IsBankOnSave).
- Counter Id string is an unvalidated join key across 6+ collections.
- Where it's already right: PreviousByte, MidwayExitBankDetector, the real enums, the deliberate SnesState string constants.

### Observability
- Seven catch blocks, one log call; the "exceptions are control flow" contract leaked from Status() into ReadWramByte/Hook.Poll/Write where nothing carries the news.
- The log knows about WRAM but not the component's own decisions (ready flips, re-arm skip, timerActive gating, banking, kill rules) — the two newest features are entirely on the blind side.
- Event-driven log with no heartbeat: a ten-minute gap is consistent with five different failures.
- Diagnostics run synchronously on the UI thread with AutoFlush per line; no rotation or size cap.
- No diagrams anywhere; SnesConnection.Tick's interlock and KillCounter's slot state machine each deserve one.
