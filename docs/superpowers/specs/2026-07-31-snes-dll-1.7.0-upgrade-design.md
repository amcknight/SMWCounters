# SNES.dll 1.7.0 upgrade — pinned bump + ROM identity in the debug trail

**Date:** 2026-07-31 · **Pin:** `lib/SNES.dll` v1.6.0 → v1.7.0

## Goal

Move the pinned `SNES.dll` from v1.6.0 to v1.7.0 and adopt the release's new
ROM-identity surface where it pays: the debug log. SMWCounters gets a
counters-debug.log that names the ROM each session ran against, and the
header-aware decline messages v1.7.0 added surface in the settings status line
for free.

## Compatibility finding — this is a drop-in bump

v1.7.0's one breaking change is `Smc()`: it returns an identity slug
(`super-marioworld-a0da-67ba8a`) rather than a ROM path. **SMWCounters never
calls `Smc()`.** The API diff `d5777e6..23a56a2` over `src/SNES/` is purely
additive for everything the component consumes — `Attach`, `Ready`,
`GetOffset`, `Read1`, `Generation`, and the `EmuStatus` fields the dot, the
status line, and the log already read. `RomIdentity Rom()`, `string
WindowTitle()`, `Status().Rom` and `Diag.RomSlug` are new members alongside
them.

So no consumer code *must* change. What follows is what we choose to adopt.

## Decisions

1. **Adopt identity in observability only.** The slug and window title go into
   the `SNS` debug-log lines. Nothing branches on identity — the consumer
   contract is explicit that `Rom`/`RomSlug` are render-only (churn tier), and
   v1.7.0 documents a transient where an identity can commit wrong near a ROM
   load before correcting itself. Logging tolerates that; logic would not.
2. **The slug joins the log-on-change key.** An identity change alone emits a
   line, so a ROM swap that never disturbs the WRAM bind still leaves a trace —
   and the documented corrective second edge is captured as evidence rather
   than swallowed. Cost is a few extra lines around load events, which is what
   counters-debug.log is for.
3. **The window title is decoration, never a key.** It is rendered when
   non-empty but never participates in change detection: emulators decorate
   titles with FPS and other churn, and per the contract it is deliberately
   unparsed.
4. **`Process.MainWindowTitle` stays off the hot path.** It is refreshed inside
   `Tick()` only when the slug changes or the process is (re)acquired — the
   moments it is informative — rather than on every 15 ms tick.
5. **No UI change.** The status pixel mapping, the settings status line, and
   counter behavior are untouched. The header-aware `LastError` (e.g. *"SA-1
   cartridge detected (slug); SA-1 WRAM discovery is not supported"*) already
   flows through `SnesConnection.ErrorSuffix`, so better decline text arrives
   with the binary and needs no code.
6. **No release.** Lands on `master` without a version bump; the pin ships with
   whatever release comes next.

## The bump

- Build `src/SNES/SNES.csproj` Release from the sibling `snes_offsets` checkout
  at `23a56a2` (it ProjectReferences `../../../LiveSplit/src/LiveSplit.Core`,
  which is present locally). Verify `FileVersion 1.7.0.0` on the output before
  copying.
- Overwrite `lib/SNES.dll` and commit it — the `.gitignore` carve-out
  (`!lib/SNES.dll`) already permits the tracked binary.
- `CREDITS.md`: pin note v1.6.0 → v1.7.0.
- **No csproj change.** The reference is a `HintPath` into `lib/` with
  `Private=true`, and `CopyToLiveSplitComponents` already deploys
  `SMWCounters.dll` + `SNES.dll` as a pair.

## Code changes

### `Snes/SnesConnection.cs`

- `RomSlug` — `Status.Rom?.Slug ?? ""`. Free: `Rom` rides the `EmuStatus`
  snapshot already taken each tick.
- `WindowTitle` — cached string, refreshed from `emu.WindowTitle()` inside
  `Tick()` when the slug changes or a process is newly acquired; cleared on
  detach.

### `Diagnostics/DebugLogger.cs`

`LogStatus` forwards the slug and window title to the filter as plain strings.
The method keeps its existing `SNES.EmuStatus` parameter; the two new values
come from the connection.

### `Snes/StatusChangeFilter.cs`

- Slug appended to the change key.
- Line renders `rom=<slug>` and `win="<title>"`, each omitted when empty, after
  the existing `rivals`/`contested`/`reg`/`cooldown`/`err` fields. The class
  stays primitives-in / line-out with no SNES.dll types.

Example:

```
SNS state=Searching gen=0 base=0x0 method=None rebind=None rom=super-marioworld-a0da-67ba8a win="clean - Snes9x 1.63"
SNS state=Resolved gen=1 base=0x7E0000 method=Structural rebind=Fresh rom=super-marioworld-a0da-67ba8a win="clean - Snes9x 1.63" scanMs=412
```

## Testing

**Unit (CI-safe):** extend `StatusChangeFilterTests` — a slug change alone
emits a line; `rom=`/`win=` render and are omitted when empty; an unchanged
tick including an unchanged slug still emits nothing. Existing tests unchanged.

**Build:** clean build against the new pin; full suite green.

**Live gate (no merge without it):**

1. **Close LiveSplit first**, build, confirm both DLLs deployed (timestamps) —
   the stale-DLL trap invalidates any live evidence gathered against a locked,
   un-replaced DLL.
2. Real emulator with SMW loaded: the dot behaves as before (yellow →
   blue/green family), counters count.
3. `counters-debug.log` carries `rom=` and `win=` on the SNS trail, and the
   identity is stable rather than churning while the ROM sits loaded.
4. Watch that v1.7.0's background ROM scan (a periodic re-digest, ~2 s
   interval) does not disturb the component's tick loop — no visible stutter,
   no new decline errors.

## Risks

- **Identity churn near loads** is a documented, accepted v1.7.0 residual. It
  reaches only the log here, by decision 1. If the live gate shows churn while
  a ROM sits *steadily* loaded, that is a different bug and blocks the bump.
- **Build coupling** — producing the Release DLL requires the sibling LiveSplit
  checkout that `SNES.csproj` references. Present locally; unchanged from the
  v1.6.0 bump.

## Out of scope

- Any logic keyed on ROM identity (reset triggers, per-hack behavior).
- A slug → friendly-hack-name map (documented as consumer-side future work in
  the snes_offsets spec; would be a new hand-maintained table).
- Status-line or status-pixel changes.
- SMWCounters version bump / release.
